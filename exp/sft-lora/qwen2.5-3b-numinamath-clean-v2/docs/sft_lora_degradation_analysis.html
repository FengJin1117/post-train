SFT-LoRA 为什么持续导致数学能力退化

基于 Qwen2.5-3B-Instruct 与 Qwen2.5-3B Base 的 clean-10K 实验、全部 checkpoint gate、完整评测、训练日志和数据抽查形成的诊断报告。

执行结论

退化的主因不是 LoRA 本身，也不是单一学习率问题，而是优化目标错位。
当前 SFT 正在稳定地把模型拉向一个“答案更长、质量更弱、停机更差”的教师分布。B1 的低学习率和小 LoRA 只让这种迁移更慢；B2 的高学习率、all-linear 和 2 epochs 则更快、更彻底地放大了它。

建议决策：停止继续扩展当前 clean-10K 的 SFT 配方；先修数据与生成目标，再做一个 2K–5K 的高质量 SFT bootstrap。GRPO 可行，而且比继续盲调 SFT 更契合“可验证数学正确性”的目标，但应从具备稳定指令与数学能力的模型开始。

根因排序

优先级根因证据与机制置信度
1 教师答案质量不足，清洗只验证格式 过滤器保证“唯一 boxed 且与 answer 字段一致”，但没有验证 answer 或推理正确。随机抽查已发现过程算出 π/4，最终却标成 √π/2 的明显错标。SFT 会无条件模仿错解。 已证实
2 长度分布和停机目标严重错位 训练集强制 solution ≥128 tokens，平均 502.7 tokens；AoPS 3,417 条平均 843.5 tokens。长答案中 EOS 只占极小的 token loss 权重，模型却被大量训练去“继续写”。生成截断率随配方强度显著上升。 高
3 数据分布不等于目标 benchmark 分布 训练配额按来源与题型平衡，不按可验证难度、解答正确率、目标 benchmark 技能或输出长度平衡。仅 83 条 amc_aime；30% synthetic；validation 又以 cn_k12 为主，因此 validation loss 与 GSM8K/MATH-500 脱钩。 高
4 能力覆盖不足导致灾难性行为迁移 Instruct 模型原有高质量数学策略被 10K 弱教师答案覆盖；raw base 则没有先建立稳定的 instruction/termination 行为。B1/B2 都退化说明换 base 不能修复数据目标问题。 高
5 配方放大问题，但不是起因 B2 的 5e-5 + all-linear + 2 epochs 产生最严重停机退化；然而 B1 和 Instruct 的低 LR 配方也从 checkpoint-50 即退化，所以继续只调 LR/rank 很难翻转结果。 已证实
次要但应单独验证：raw base 在 ChatML 协议下本身已有终止不稳，完整 GSM8K 的 max-token rate 为 25.3%。这不是 SFT 退化的全部原因，但说明直接从 generic raw base 做数学指令 SFT 风险较高。模板与 LoRA merge 没发现直接错误：训练标签含 <|im_end|>，训练/评测均使用 qwen2_5。

SFT 改进建议

目标应从“拟合更多数学解答 token”改为“只模仿已验证、短而完整、能稳定终止的优质轨迹”。

立即止损

  1. 不再训练当前 clean-10K 的 E2/E3/B3；它已经在三种起点/配方上重复失败。
  2. 把 benchmark gate 前移到每 10–20 steps，并加入 max-token < 5%、重复率、输出长度中位数门禁。
  3. checkpoint 选择只依据固定门禁和完整 benchmark，不依据 validation loss。

重建一个可用的 SFT bootstrap

  • 规模：先做 2K–5K，不要先追求 20K。每条都应经过答案验证或强模型 rejection sampling。
  • 长度：去掉 solution ≥128 的下限；建议中位数 200–500 tokens，控制 95 分位数，保留大量简洁正确答案。
  • 正确性：用 math_verify/SymPy/规则答案验证；复杂题用多样本一致性或强 RM 过滤。过滤“boxed 与 answer 一致”不等于正确。
  • 终止：清除答案后的冗余总结；确保最后答案后立即 EOS。可对 EOS/最后一段提高 loss 权重，或至少提高短而稳定样本占比。
  • 数据混合：若从 Instruct 开始，加入 20%–30% 原能力 replay 数据，避免覆盖原有 instruction 与停机行为。
  • 配方：先用 1e-6 / 2e-6 / 5e-6 三点小规模消融，LoRA rank 8–16；达到门禁后再扩数据或 all-linear。

GRPO 可行性与推荐

可行，且方向正确；但 GRPO 不是坏 SFT 数据的自动修复器。

数学题有可验证最终答案，适合 outcome reward。GRPO 可以直接奖励正确答案并惩罚超长、重复和格式失败，正好针对当前 SFT 的主要缺陷。Qwen2.5-Math 官方路线本身也是先用 rejection sampling 改进 SFT，再在最终 SFT 模型上做 GRPO。

首选模型

Qwen2.5-Math-7B-Instruct

已有数学先验、指令格式和足够非零正确率，GRPO 组内更容易产生 reward 方差。先 LoRA-GRPO 验证，资源允许再做 full GRPO。

低成本备选

Qwen2.5-Math-1.5B-Instruct

适合验证 reward、数据和训练管线，但能力上限较低。不要优先使用当前退化 LoRA 或 generic Qwen2.5-3B raw base。

阶段唯一 prompts用途通过条件
管线 pilot1K–2K验证 reward、格式、长度与吞吐reward_std 非零；截断率下降；无 reward hacking

弱模型 / 1.5B20K–50K需要更多覆盖，但先保证可解题比例大量组内全错时应换更强 policy 或降低难度

GRPO 每个 prompt 会生成多条 completion。10K prompts × 8 generations 已对应至少 80K 条 rollout；数据质量和难度分层通常比盲目增加唯一 prompt 更重要。

奖励与稳定性配置

  • 主奖励：accuracy，权重必须占主导；gold 使用可解析的最终答案，不使用未经验证的长 solution。
  • 辅助奖励：format、repetition penalty、soft overlong；避免 format reward 过强导致只学格式。
  • 采用 DAPO 风格的 dynamic_sample、overlong_filter、soft_overlong 与 token-level loss，直接处理全同奖励和超长噪声。
  • 起步建议：num_generations=8、temperature 0.8–1.0、completion 2K–4K、低 LR（LoRA 约 1e-6 量级，full 更低）、非零小 beta，并监控 KL。
  • 核心监控：accuracy reward、reward_std、frac_reward_zero_std、clipped_ratio、completion length、重复率、独立 benchmark。
