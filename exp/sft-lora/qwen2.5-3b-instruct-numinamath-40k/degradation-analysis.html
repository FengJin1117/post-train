SFT-LoRA 训练后模型退化分析与改进方案

实验：Qwen2.5-3B-Instruct + NuminaMath-1.5 40K · 日期：2026-06-06
实验目录：exp/sft-lora/qwen2.5-3b-instruct-numinamath-40k
结论：本次退化不是评测随机波动，也不能只归因于少量无限重复样本。 核心原因是使用高学习率、全线性层 LoRA，在两个 epoch 内将基模强已有能力拉向一个题型与答案格式混杂的训练分布； 同时模型的停止与生成稳定性明显受损。建议停止沿用当前 40K 配方，先用更干净、格式统一的 10K/20K 数据， 以更低学习率和更短训练进行受控消融。

LoRA 模型中位输出反而更短，但均值和 P90 急剧增大，呈现“双峰”行为： 多数样本较快结束，另一批样本进入重复循环直到上限。MATH-500 中 66 条达到 8192 token， 其中仅约 3.0% 得分正确。

2.2 排除异常长输出后，基础能力仍明显下降

GSM8K61.41%64.88%无限重复解释了一部分退化，但远不足以解释与 84.69% 基线的差距。

因此需要同时处理两类问题：生成稳定性与数学能力遗忘/偏移。仅在评测时降低 max_tokens 或增加 repetition penalty，只会缓解成本和循环，不会恢复主体准确率。

3. 根因分析与优先级

优先级根因证据判断
高置信 训练数据题型与目标评测混杂，答案协议不统一 训练集包含 29,045 道 word problem、5,515 道 proof、5,403 道 MCQ； 仅 60.42% solution 含 \boxed{}，39.58% 不含。 其中 olympiads 与 cn_contest solution 的 boxed 比例为 0%。 模型同时学习“证明结束”“选择题答案”“自由格式解答”和 boxed 数值答案，削弱统一可抽取终答行为。
高置信 更新强度对强基模过大，产生能力遗忘 LR 1e-4、2 epochs、all-linear、29.93M 可训练参数； MATH-500 所有难度层均下降，正常停止样本也明显退化。 当前配置更像强分布迁移，而不是在已有数学能力上做小幅增强。
高置信 部分训练解答存在格式噪声 1,113 条 solution（2.8%）花括号不平衡；143 条 solution 仍含 URL； 训练集中 5,219 条记录的 answer 为 proof，2,357 条为单字母选择答案。 有效性标签不等于适合 SFT；格式噪声可能放大 LaTeX 错乱和重复生成。
中置信 高难竞赛数据比例过高，且不等于高质量推理监督 olympiads / aops_forum / cn_contest / amc_aime 共 18,000 条（45%）； 其中 proof 与无 boxed 解答占比较高。 对 3B 模型而言，难题的低质量或跳步解答可能教会错误模式，而非提升推理。
中置信 缺少 benchmark 门禁和 checkpoint 早停 只在同源 validation 上监控 loss；checkpoint-500、1000、1248 未进行小规模 GSM8K/MATH 对比。 无法发现能力可能在早期就开始退化，也无法选择 benchmark 最优 checkpoint。
次要 评测生成上限过大，放大循环成本 max_tokens 为 8192；LoRA MATH-500 有 66 条生成到上限。 这是症状放大器，不是主体能力下降的根因。可设上限保护，但不能替代重训。

当前抽样逻辑主要按 source 和大类配比，而不是按“解答正确性、格式完整性、终答可抽取性、推理难度适配” 进行排序。数据虽通过 problem_is_valid=Yes 和 solution_is_valid=Yes，仍不代表适合直接训练强指令模型。

5. 推荐改进方案

5.1 第一优先级：建立干净、统一的 SFT 数据协议

推荐首轮重训数据：10K 或 20K，而不是立即再跑 40K。只保留可验证数值/表达式答案， 每条 solution 统一以 Therefore, the final answer is \boxed{...}. 或等价模板结束。
规则建议目的
题型首轮移除全部 proof 与 MCQ让监督目标与 GSM8K / MATH-500 数值解题一致。
答案格式要求 answer 非 proof、非单字母，并保证 solution 最后含唯一 boxed 终答强化稳定终答与可抽取性。
格式质量过滤括号/花括号明显不平衡、URL、异常重复、超长解答减少错误 LaTeX 与循环模式。
长度优先 128–1536 tokens 的解答，P99 做硬限制避免用极长低密度推理监督 3B 模型。
难度以中等难度、可完整求解样本为主；竞赛难题不超过 25%先保住基模能力，再逐步提升难题。
保留能力混入 10%–20% 高质量通用指令或基模自蒸馏数学样本降低灾难性遗忘和风格漂移。
去重/污染对 GSM8K、MATH-500、AIME、GAOKAO 做近似去重保证结果可信，避免数据污染。

5.2 第二优先级：降低训练更新强度

参数当前推荐首轮理由
数据量40K10K，验证后扩到 20K更快做因果消融，减少坏数据累计影响。
Epoch21先观察一次完整遍历是否已足够。
Learning rate1e-41e-5 或 2e-5降低对已有能力的破坏。
LoRA targetall-linear先试 q_proj,k_proj,v_proj,o_proj缩小行为改写范围。
LoRA rank / alpha16 / 328 / 16 或保守保留 16 / 32先验证较小容量是否足够。
Checkpoint500 steps100–200 steps配合 benchmark 门禁及时发现退化。

5.3 第三优先级：将 benchmark 门禁纳入训练流程

每个候选 checkpoint 先跑低成本门禁，只有不低于基线阈值才继续完整评测：

门禁样本量通过建议
GSM8K 固定子集200不低于 base 子集准确率 - 2 个百分点
MATH-500 固定子集100，覆盖五个 level不低于 base 子集准确率 - 3 个百分点
生成稳定性同一门禁集合达到 max_tokens 的比例 < 1%，无高频重复循环
格式同一门禁集合终答可抽取率 > 98%

建议同时评测 checkpoint-500、1000、1248，以确认退化发生在训练早期还是后期；这项实验成本低、诊断价值高。

5.4 评测侧保护措施

  • 将 GSM8K 的 max_tokens 临时限制在 1024，MATH-500 限制在 2048 或 4096，避免循环样本拖垮评测。
  • 记录 stop_reason=max_tokens 比例、平均/中位/P90 输出 token、boxed 终答提取率。
  • 可做 repetition penalty 消融，但应保持基模与微调模型评测参数一致；它不能替代重训。
  • AIME25 当前因 GPU OOM 没有有效结果，应在空闲 GPU 上重新运行。

7. 验收标准与决策规则

  1. 先保能力：GSM8K 与 MATH-500 门禁不得出现超过 2–3 个百分点的下降。
  2. 再看提升：完整评测至少一个 benchmark 高于基线，并且另一项无明显退化。
  3. 生成必须稳定：达到生成上限比例低于 1%，无明显重复循环。
  4. 只有 E1 通过后才扩数据：若 10K 保守配方仍退化，优先继续修数据协议，不要直接上 40K/100K。
  5. 不要用 validation loss 代替 benchmark：checkpoint 选择应加入固定 benchmark 子集结果。

8. 最终判断

NuminaMath-1.5 可以作为候选数据池，但当前 40K 混合采样不能作为可复用训练集。 本次实验已证明训练链路和 LoRA 工程配置可以跑通，但也证明“有效性标签 + 来源配比”不足以保证数学能力提升。 下一轮最有价值的工作不是增加数据量，而是统一监督协议、降低更新强度、建立 benchmark 门禁。

最推荐的下一步是：先评测现有 checkpoint-500 / 1000 / 1248 的固定小集合，然后运行 干净 10K、仅数值解题、统一 boxed、LR 1e-5、1 epoch、attention-only LoRA。
