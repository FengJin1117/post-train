simplescaling/s1K：Qwen2.5-Math-1.5B 复刻可行性分析

使用 Qwen/Qwen2.5-Math-1.5B tokenizer 的精确统计；目标训练 context length = 4096。分析日期：2026-06-13 UTC。

结论

原始 s1K 配方无法在 4096 context 下直接复刻。 原始训练序列中位数为 5,897 tokens，仅 127/1000（12.7%） 能完整放入 4096；数学样本中有 816/877（93.0%） 超长。

最关键判断：s1K 的长度主要来自 Gemini 蒸馏推理轨迹，而不是题目。题目平均仅 127 tokens， 但 thinking 平均 4,692 tokens，最终 attempt 平均 803 tokens。Qwen2.5-Math-1.5B 的 4096 限制会直接切断核心训练信号。

建议：若目标是忠实复刻 s1 的长推理行为，至少使用 8192 context；若必须使用 4096， 应先对 thinking 做短链蒸馏/重写，并将完整序列控制在约 3,800 tokens 内。不要直接右截断原始数据。

统计口径

数据集共 1,000 条，无重复 question；每条均有且只有一条 thinking_trajectories。 依据原 s1 仓库的 data/tokenization.py，训练 assistant 内容是：

<|im_start|>think\n{thinking_trajectories[0]}\n<|im_start|>answer\nAnswer: {attempt}

“完整序列”包含 Qwen chat template、question、上述 thinking 和 attempt。分词器为 Qwen/Qwen2.5-Math-1.5B；原实验使用 Qwen2.5-32B-Instruct tokenizer 和 block_size=32768，并训练 5 epochs。

tokenizer 配置本身报告较大的 model_max_length，但本报告严格按项目给定的 Qwen2.5-Math-1.5B 实际训练约束 4096，以及推理 max_tokens=3072 做决策。

4096 右截断虽然按 token 数仍保留 68.3% 的监督内容，但只有 20.7% 的样本能进入最终 answer， 其余样本会以未完成的思考结尾。这样训练会强化冗长展开，却大多不监督“收束并给出答案”的行为。

若直接丢弃所有超长样本，只留下 127 条，则只保留原数据约 5.8% 的 assistant 监督 token， 且任务组成明显偏向 science/crossword，不再代表原 s1K。

推理预算 max_tokens=3072

仅 90/1000（9.0%） 的原始 assistant response 能在 3072 新 token 内完整生成； 即使只看 thinking，也仅 122/1000（12.2%） 能完整生成。训练时保留原长轨迹、推理时只给 3072， 存在明显的训练/推理长度错配。

  1. 忠实复刻优先：将训练 context 提升至 8192；12 条超长样本可单独裁剪或丢弃。
  2. 必须 4096：对每条 thinking 做语义压缩，而非 token 级硬截断；预留 question/template 与约 800-token attempt，建议 thinking 目标上限约 2,800–3,000 tokens。
  3. 推理预算同步：由于 max_tokens=3072，短链蒸馏后的 response 最好也控制在 3,072 内，否则训练目标仍无法在部署时完整生成。
  4. 保持分布：压缩后按 cot_type/source_type 分层抽查，避免 4k 适配过程进一步偏向较短的 science/crossword。

其他内容信号

  • attempt 中含 \boxed：929 条（92.9%），最终答案格式总体稳定。
  • thinking 中含 “Alternatively”：132 条（13.2%）；含 “Wait”：19 条（1.9%）。Gemini 轨迹存在一定回溯/替代路径，但 “Wait” 并不是主要模式。
  • 最长完整序列为 9,108 tokens；所有样本均小于 16,384，原始 32k block_size 实际有较大余量。
